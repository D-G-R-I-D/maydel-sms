# Handoff → Frontend: M1.2 part 3 — PDF report cards & term comparison (E5.6, E5.6b, E5.8)

> Backend status as of 2026-10-14. Contract: `contracts/openapi.json` (run `npm run api:types`). Builds on part 2 (report preview).

## What exists now
- **PDF report card**: A4 portrait, one page, modelled on the school's Excel result sheet.
  - Crest, school details, student details and photo.
  - One column per score component, then total, grade, remark, class average and the teacher's per-subject comment.
  - Summary strip: cumulative total, pupil's average, class average, position, annual average.
  - Term comparison, grading key, form teacher's and principal's comments, resumption date.
  - Up to 15 subjects fit on one page (tested). Drafts carry a pale "DRAFT – NOT FINAL" watermark.
- **Class PDF**: one file for the whole class, one page per student with results, for printing.
- **Term comparison** on `ReportCard` (and in the PDF):
  - A second-term report compares with first term; a third-term report compares with first and second.
  - It covers each subject and the overall average, with a trend (`Improved` / `Steady` / `Declined`; movements under 1 mark count as steady).
  - The annual (cumulative) average shows once there are two or more terms.
  - **Only published earlier terms are used**, so drafts never leak.

## Endpoints
| Method & path | Who | Response | Errors |
|---|---|---|---|
| `GET /api/reports/{studentId}/{termId}/pdf` | Admin; teachers of the class | `application/pdf` (`Content-Disposition` with a file name like `Chiamaka Okeke - First Term 2026-2027.pdf`) | 403, 404, 422 |
| `GET /api/reports/class/pdf?classRoomId&termId` | Admin; teachers of the class | `application/pdf`, one page per student with scores | 403, 404, 422 `report.nothing_to_publish` |

## New `ReportCard` fields (additive)
```ts
totalScore: number;                       // CUMM. TT (sum of subject totals)
previousTerms: { termId: string; number: "First" | "Second" | "Third"; term: string; average: number; position: number | null; classSize: number }[];
averageChange: number | null;             // this term's average − last published term's
trend: "Improved" | "Steady" | "Declined" | null;
cumulativeAverage: number | null;         // annual average, null until there are 2+ terms
// each subjects[i] also has:
previousTerms: { number: "First" | "Second" | "Third"; term: string; total: number; grade: string | null }[];
changeFromLastTerm: number | null;        // this term's total − last published term's total for that subject
trend: "Improved" | "Steady" | "Declined" | null;
```

## UI
1. **Download buttons:**
   - "Download PDF" on the report card preview.
   - "Download class PDF (print)" on the class reports page.
   - Proxy both through the BFF like photos (e.g. `/api/media/reports/{studentId}/{termId}/pdf` and `/api/media/reports/class/pdf?...`). Stream the bytes and pass `Content-Type` and `Content-Disposition` through.
   - Opening in a new tab shows the browser's PDF viewer.
2. **Term comparison on the preview:**
   - Per subject: an extra column per earlier term, plus a change cell (green `+5.5`, red `−3`, grey "Steady").
   - Overall: a small card "First Term: avg 74.26, 2nd of 3 → This term: avg 72.08 (−2.18)", plus the annual average when present.
   - Hide all of it when `previousTerms` is empty (first term, or earlier terms not published).
3. Later (portal, M1.3): parents and students download the **published** PDF of their own child from the portal. A separate portal endpoint will enforce that.

## Notes
- The grading key on the PDF comes from Settings → Assessment. The school's real Excel sheet uses 8 bands (A+ 95+, A 90+, B+ 80+, B 70+, C+ 60+, C 50+, D 40+, F). The seeded default has 6 (A 70+ …), so the user is deciding which to keep.
- Behaviour/affective ratings and clubs (on the Excel sheet) are story E2.5 and aren't modelled yet.
- School name, address and contacts come from the API's `School` configuration until the school profile screen (E2.6).
