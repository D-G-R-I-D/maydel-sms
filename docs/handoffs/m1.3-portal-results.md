# Handoff → Frontend: M1.3 — Portal results for parents & students (E6.1 part, E6.2)

> Backend status as of 2026-10-14. Contract: `contracts/openapi.json` (run `npm run api:types`).

## What exists now
- **Who uses the portal:** parents (role `Parent`) and students (role `Student`) only. Staff get 403 here and keep using the staff API.
  - Someone who is both teacher and parent has both roles, so they can use both.
- **Children:**
  - A parent sees their **active** linked children. Suspended, withdrawn and graduated children drop out.
  - A student sees only themselves.
- **Only published results are visible.** Drafts never appear in lists, and opening a draft directly gives 404 `report.not_published` (tested).
- **No probing:** another family's child gives 404 `portal.student_not_found` on every endpoint, including the photo.
- The report card is the same `ReportCard` shape as the staff preview, with frozen published figures:
  - subjects, components, comparison with earlier published terms, behaviour and clubs, comments, attendance, grading key.
- PDF download is the same A4 report card, without a watermark (it's always published).

## Endpoints (policy: Parent or Student)
| Method & path | Response | Errors |
|---|---|---|
| `GET /api/portal/children` | `PortalChild[]`, sorted by first name | 401, 403 |
| `GET /api/portal/children/{studentId}/photo` | image (private cache, `?v=photoVersion`) | 404 |
| `GET /api/portal/children/{studentId}/results` | `PortalResultSummary[]`, newest first | 404 `portal.student_not_found` |
| `GET /api/portal/children/{studentId}/results/{termId}` | `ReportCard` | 404 `portal.student_not_found` / `report.not_published` |
| `GET /api/portal/children/{studentId}/results/{termId}/pdf` | `application/pdf` with `Content-Disposition` file name | 404 as above |

```ts
type PortalResultSummary = {
  termId: string; number: "First" | "Second" | "Third"; term: string; // "First Term"
  session: string; classRoom: string;                                    // class at the time of that report
  average: number; position: number | null; classSize: number; publishedAt: string | null;
};
type PortalChild = {
  studentId: string; name: string; admissionNumber: string; classRoom: string | null;
  photoVersion: string | null; latestResult: PortalResultSummary | null;
};
```

## UI to build (turn on the portal "Results" tab)
1. **Children switcher:**
   - Parents with more than one child get a switcher (avatar chips or a select) in the portal header, remembered in the URL, e.g. `/portal/results?child=<id>`.
   - Students and single-child parents don't see a switcher.
2. **Home (`/portal`):**
   - Show a card per child: photo, name, class, and the latest result (term, average, "3rd of 25"), linking to it.
   - If nothing is published yet: "No results published yet. You'll see them here once the school releases them."
3. **Results (`/portal/results`):**
   - A list of published terms grouped by session: term, class, average, position, and a "View" button.
   - Empty state as above.
4. **Report card view (`/portal/results/[studentId]/[termId]`):**
   - The same read-only report card component as the staff preview, without edit controls, draft warnings or publish actions.
   - Keep it phone-first: put the subjects table in a horizontal scroll container, and show the summary strip (average, position, class average) at the top.
   - Add a "Download PDF" button, proxied through the BFF like photos (e.g. `/api/media/portal/children/{id}/results/{termId}/pdf`), passing through `Content-Type` and `Content-Disposition`.
5. **Photos** go through `/api/portal/children/{id}/photo`, not the staff photo route (that one is staff-only).
6. Mark the portal nav "Results" item `ready: true`. Fees and Attendance stay "Soon".
7. On a 404 `report.not_published` or `portal.student_not_found`, show a friendly not-found state with a link back to Results.
