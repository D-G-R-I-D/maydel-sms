# Handoff → Frontend: Student & staff photos (completes E3.1 / E4.1)

> Backend status as of 2026-10-13. Contract: `contracts/openapi.json` (run `npm run api:types`). Design: ADR-006.

## What exists now
Admins can upload, replace and remove student and staff photos. Every upload is checked (real JPEG/PNG/WebP only, ≤ 12 MB) and **re-encoded on the server**: resized to ≤ 800 px, rotated upright, all metadata including phone GPS location removed. Photos are private: the API only serves them after the same access check as the record.

## Endpoints
| Method & path | Who | Request → response | Errors |
|---|---|---|---|
| `PUT /api/students/{id}/photo` | Admin | `multipart/form-data`, field **`file`** → `PhotoInfo { version, width, height }` | 400 `validation` (`errors.file`), 404 |
| `DELETE /api/students/{id}/photo` | Admin | → **204** | 404 `photo.not_found` |
| `GET /api/students/{id}/photo` | Staff | → `image/jpeg` bytes, `ETag`, `Cache-Control: private, max-age=86400` (supports `If-None-Match` → 304) | 404 `photo.not_found` |
| `PUT / DELETE / GET /api/staff/{id}/photo` | same (GET: Staff) | same | same |

New field **`photoVersion: string | null`** on `StudentListItem`, `StudentDetail`, `StaffListItem` and `StaffDetail`. `null` means no photo: show initials or an avatar placeholder.

## How the UI should load photos (BFF rule: the browser never calls the API)
1. Add a BFF route handler, e.g. `app/api/media/students/[id]/photo/route.ts` (and `staff/[id]`). It forwards the request to the API with the bearer token from the cookie, passes `If-None-Match` through, and streams the response back with the API's `Content-Type`, `ETag` and `Cache-Control`. Map 401/403/404 to the same status with no body.
2. In `<img>` (or `next/image` with `unoptimized`), use `src={`/api/media/students/${id}/photo?v=${photoVersion}`}`. The `?v=` makes a replaced photo a new URL, so the 1-day private cache is safe.
3. **Upload:** a client form posts the file to a BFF route (e.g. `PUT /api/media/students/[id]/photo`). The route applies the usual `crossSiteRejection` check and re-sends the multipart body to the API with the bearer token. Then refresh the record (or use the returned `version`).
4. **Upload UI:** accept `image/jpeg,image/png,image/webp`, show a preview, and validate the 12 MB limit client-side. Show `errors.file` from the problem response ("Upload a JPEG, PNG or WebP photo (up to 12 MB)"). iPhone HEIC photos aren't accepted. The message tells admins to use JPEG; phones usually offer "Most Compatible" when sharing.
5. Avatars on student and staff lists and profiles; a "Change photo" / "Remove photo" menu for Admin.
