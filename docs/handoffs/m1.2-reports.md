# Handoff → Frontend: M1.2 part 2 — Comments, report preview, publish (E5.3, E5.4, E5.5)

> Backend status as of 2026-10-14. Contract: `contracts/openapi.json` (run `npm run api:types`). Builds on part 1 (score grid). Part 3 is the PDF report card.

## What exists now
- **Class report list:** every active student with subjects scored, average, position, status, attendance and comment flags.
  - *Draft:* figures are live and change as scores change.
  - *Published:* figures are frozen.
- **Report card preview:** components, totals, grades, remarks, subject class highest / lowest / average, overall average, class average, position (competition ranking 1, 2, 2, 4), class size, attendance, comments, grading key and next-term date.
- **Comments:**
  - the form teacher writes the form teacher's comment;
  - admins write the principal's comment.
- **Attendance:** the form teacher or an admin enters "days school opened" and each student's "days present" for the term. This is manual until the daily register (E9) exists.
- **Publish (admin):** freezes the figures and locks scores, comments and attendance. It's refused until attendance is entered for everyone being published. Students with no scores are skipped and listed. Publishing again after a change recalculates everything.
- **Unpublish (admin):** reopens the whole class or chosen students for corrections. Every publish and unpublish is audited.

## Endpoints (`/api/reports`)
| Method & path | Who | Body → response | Errors |
|---|---|---|---|
| `GET /class?classRoomId&termId` | Admin; form teacher or any subject teacher of the class | → `ClassReportSummary` | 403 `report.not_allowed`, 404 |
| `GET /{studentId}/{termId}` | same | → `ReportCard` | 403, 404, 422 `report.no_class` |
| `PUT /{studentId}/{termId}/form-teacher-comment` | form teacher of the class, Admin | `{ comment }` (≤ 2000; empty clears) → `ReportCard` | 400, 403 `report.not_form_teacher`, 422 `report.published` |
| `PUT /{studentId}/{termId}/principal-comment` | **Admin** | `{ comment }` → `ReportCard` | 400, 403, 422 `report.published` |
| `PUT /attendance` | form teacher of the class, Admin | `{ classRoomId, termId, daysOpened (1–200), entries: [{ studentId, daysPresent }] }` → `ClassReportSummary` | 400 (`daysOpened`, `entries[i].daysPresent`), 403, 422 `report.published` |
| `POST /publish` | **Admin** | `{ classRoomId, termId }` → `PublishResult { published, classAverage, skipped: [{ studentId, name, reason }] }` | 404, 422 `report.attendance_missing` / `report.nothing_to_publish` |
| `POST /unpublish` | **Admin** | `{ classRoomId, termId, studentIds?: string[] }` (omit for the whole class) → `{ unpublished }` | 404 |

```ts
type ClassReportSummary = {
  classRoomId: string; classRoom: string; termId: string; term: string; formTeacher: string | null;
  subjectsOffered: number; classAverage: number; daysOpened: number | null; publishedCount: number; draftCount: number;
  rows: { studentId: string; admissionNumber: string; name: string; subjectsScored: number;
          average: number | null; position: number | null; status: "Draft" | "Published";
          daysPresent: number | null; hasFormTeacherComment: boolean; hasPrincipalComment: boolean }[];
};
type ReportCard = {
  studentId; studentName; admissionNumber; sex; dateOfBirth; house; photoVersion;
  classRoomId; classRoom; termId; term /* "First Term" */; session; termEndsOn; nextTermBegins: string | null;
  status: "Draft" | "Published"; publishedAt: string | null;
  components: { id; name; maxScore }[];                       // column order
  subjects: { subjectId; subject; scores: { componentId; score: number | null }[]; total; grade; remark; comment;
              classHighest; classLowest; classAverage }[];
  average: number | null; classAverage: number; position: number | null; classSize: number;
  daysOpened: number | null; daysPresent: number | null; daysAbsent: number | null;   // null = attendance not entered
  formTeacher: string | null; formTeacherComment: string | null; principalComment: string | null;
  gradingKey: { grade; minScore; maxScore; remark }[];
};
```

## Screens
1. **Class reports** (`/admin/reports/[classRoomId]?termId=`): admins and the class's teachers. Reach it from "My classes" (form classes) and an admin "Reports" page listing all classes for the term.
   - **Table:** student, subjects scored as "n/offered" (warn when below), average, position, attendance, comment ticks, status badge. Loading, empty and error states.
   - **Admin actions:**
     - "Publish class" opens a confirm dialog with the counts ("12 will be published; 1 has no scores"). Show `skipped` afterwards.
     - A 422 `report.attendance_missing` shows its `detail` (it names the students) and links to attendance.
     - "Unpublish" (whole class, or selected rows) has a confirm.
2. **Attendance** (form teacher / admin): a "Days school opened" input plus one "Days present" number per student, with a "Mark all present" helper. Saves the class in one call. Read-only when published.
3. **Report card preview** (`/admin/reports/[classRoomId]/[studentId]?termId=`):
   - Render the card in the school's layout (biodata with photo, subject table with component columns, class stats, attendance, comments, grading key, next term begins).
   - Show a "DRAFT – figures may change" watermark when `status = Draft`.
   - Comment boxes: the form teacher's (editable by the form teacher and admins), the principal's (admins only). Show a lock when published.
   - Prev/next student navigation for the comment-writing flow.
   - The PDF download button comes in part 3.
4. Add "Reports" to the console nav for Admin and Teacher.

## Rules to mirror in the UI
- Nothing about a published report can change: scores, comments and attendance all return 422. Hide or disable the edit controls and show "Published – ask an admin to unpublish".
- Days present ≤ days opened.
- Draft figures are live; only the published figures are what parents will see (portal, M1.3).
