# Handoff → Frontend: M1.1 part 3 — Students, guardians & logins (E3.1–E3.5)

> Backend status as of 2026-10-13. Contract: `contracts/openapi.json` (run `npm run api:types`). Builds on parts 1–2. Reuse the **credential slip** from part 2.

## What exists now
- Admins admit students; the admission number `MSS/{admission year}/0001` is generated.
- Admins edit biodata, move students between classes (capacity enforced), and change status (Suspended, Withdrawn, Graduated, re-admit).
- Admins link guardians. Siblings automatically share one guardian, matched by phone in any format.
- Admins issue student and parent logins (temporary password shown once).
- All staff can search and view students. Parents and students can't use these endpoints at all; their portal comes in M1.3.

**Not yet:** student photo upload (needs the secure file pipeline, next PR), bulk import (E3.8) and promotion (E3.6).

## Students (`/api/students`)
| Method & path | Who | Body → response | Errors |
|---|---|---|---|
| `GET ?search&classRoomId&status&page&pageSize` | Staff | → `PagedResult<StudentListItem>`. `search` matches **every word** against first, middle and last name or admission number | 400 |
| `GET /{id}` | Staff | → `StudentDetail` (biodata + `guardians[]`, primary contact first) | 404 |
| `POST` | Admin | `StudentRequest` → **201** `StudentDetail` | 400, 422 `classroom.full` |
| `PUT /{id}` | Admin | `StudentRequest` → `StudentDetail` (admission number never changes) | 400, 404, 422 `classroom.full` |
| `POST /{id}/status` | Admin | `{ status: "Active"\|"Suspended"\|"Withdrawn"\|"Graduated" }` → `StudentDetail` | 400, 404, 422 `student.status_transition` / `classroom.full` |
| `POST /{id}/login` | Admin | (no body) → `IssuedCredentials` (creates or resets; username = admission number) | 404, 422 `student.inactive` |
| `POST /{id}/guardians` | Admin | `GuardianRequest` → `GuardianAdded` | 400, 404, 409 `guardian.already_linked` |
| `PUT /{id}/guardians/{guardianId}` | Admin | `{ relationship, isPrimaryContact, canPickUp }` → `StudentDetail` | 400, 404 `guardian.not_linked` |
| `DELETE /{id}/guardians/{guardianId}` | Admin | → **204** (another guardian is promoted to primary contact) | 404 |

```ts
type StudentRequest = {
  firstName: string; middleName?: string; lastName: string; dateOfBirth?: string /* YYYY-MM-DD */;
  sex?: "Female" | "Male"; stateOfOrigin?: string; lga?: string; homeAddress?: string; house?: string;
  medicalNotes?: string; classRoomId?: string; admittedOn: string /* YYYY-MM-DD; sets the admission-number year */;
};
type GuardianRequest = {
  fullName: string; phone: string; email?: string; occupation?: string; address?: string;
  relationship: "Mother" | "Father" | "Guardian" | "Other"; isPrimaryContact: boolean; canPickUp?: boolean /* default true */;
};
type GuardianAdded = { student: StudentDetail; guardianId: string; reusedExistingGuardian: boolean };
```

## Behaviour the UI must reflect
- **Phones** are stored as `+234…`. Users can type `0803 000 0000`, `+234 803…` or `(0803) 000-0000`. The server normalises the number and rejects anything that isn't a phone (`errors.phone`).
- **Sibling reuse:** when `reusedExistingGuardian` is true, show "Linked to existing guardian {name}, who is also guardian of {other children}". Their stored name and email were kept, not overwritten by what was typed.
- **Primary contact:** exactly one per student. The first guardian added becomes primary automatically, and marking another primary unsets the old one.
- **Parent username** is their email, or their phone (`+234…`) if they have no email. One parent login covers all their children. If the email already belongs to a staff account, `credentials` is null and `linkedExistingAccount` is true: "Linked to their staff account; they use their existing password."
- **Logins:** credentials are shown once (print the slip immediately). Re-issuing resets the password and signs the old sessions out. Only Active students can get a login.
- **Status:** Active ⇄ Suspended; Active/Suspended → Withdrawn or Graduated; Withdrawn → Active (re-admission). Graduated is final. Any non-active status disables the student's login immediately and removes them from their parents' portal; records are kept. Confirm before changing status, and show the 422 `detail` when a transition isn't allowed.
- **Capacity:** adding or moving an active student into a full class → 422 `classroom.full` (show `detail`).
- **Date rules:** DOB not in the future, pupil 1–25 years old at admission; admission date at most a year ahead. Field errors: `firstName`, `lastName`, `middleName`, `dateOfBirth`, `admittedOn`, `sex`, `classRoomId`, `fullName`, `phone`, `email`, `relationship`.
- `HasLogin` flags exist on list, detail and guardian rows: show a "No login" badge plus an "Issue login" action.

## Screens to build (console)
1. **Students list** (`/admin/students`, all staff): search box (debounced), class and status filters, table with admission no., name, class, status badge and login badge, plus pagination. Loading, empty and error states; works at 360 px.
2. **Admit student** (Admin): biodata form; class picker from `GET /api/academics/classrooms` (show `studentCount/capacity`, disable full classes); then go to the profile.
3. **Student profile** (`/admin/students/[id]`): biodata card (Admin can edit), class, status with a "Change status" menu (confirm dialog), guardians section (add, edit link, remove, "Issue parent login"), "Issue/reset student login" → credential slip. Teachers and bursars get a read-only view.
4. **Add guardian** dialog: phone first. Optionally search `GET /api/guardians?search={phone}` as they type and show "Existing guardian found: {name} ({n} children)" before submitting.
5. **Guardians list and detail** (`/admin/guardians`, Admin): search, children list, edit, issue login.
6. **Batch credential slips (nice to have):** on a class's student list, select students → issue logins one by one → print all slips. One `POST /login` per student; there's no bulk endpoint yet.
