# Handoff → Frontend: M1.1 part 2 — Staff & staff logins (E4.1, E1.5 admin reset)

> Backend status as of 2026-10-13. Contract: `contracts/openapi.json` (run `npm run api:types`). Builds on part 1 (`m1.1-school-setup.md`).

## What exists now
Admins can add staff. Each new staff member gets a login whose username is their email, with a **temporary password shown once**. Admins can also edit staff, change roles (Admin / Teacher / Bursar, one or more), deactivate staff, and reset a password. All staff can fetch an active-staff lookup for teacher pickers, so **part 1's teacher pickers can now be switched on**.

## Endpoints
| Method & path | Who | Body → response | Errors |
|---|---|---|---|
| `GET /api/staff?search&isActive&page&pageSize` | Admin | → `PagedResult<StaffListItem>`, by name; search matches name, email or staff number | 400 |
| `GET /api/staff/{id}` | Admin | → `StaffDetail` (with `assignments`: form classes have `subjectId: null`, plus subjects taught) | 404 |
| `POST /api/staff` | Admin | `{ fullName, email, phone?, jobTitle?, roles: ["Teacher"] }` → **201** `StaffCreated` | 400, 409 `staff.duplicate_email` / `staff.email_in_use` / `staff.email_is_student` |
| `PUT /api/staff/{id}` | Admin | `{ fullName, email, phone?, jobTitle?, roles, isActive }` → `StaffDetail` | 400, 404, 409, 422 `staff.self_lockout` |
| `POST /api/staff/{id}/reset-password` | Admin | (no body) → `IssuedCredentials` | 404, 422 `staff.self_reset` / `staff.inactive` / `staff.no_login` |
| `GET /api/staff/lookup` | any Staff | → `StaffLookupItem[]` `{ id, fullName, jobTitle }`, active only | |

```ts
type StaffCreated = { staff: StaffDetail; credentials: IssuedCredentials | null; linkedExistingAccount: boolean };
type IssuedCredentials = { userName: string; temporaryPassword: string };
```

## Behaviour the UI must reflect
- **Credentials are shown exactly once**, in the create and reset responses. Nothing can retrieve them later, so show them on a **credential slip** right away (see below) with a clear "This password won't be shown again" warning. Never store them in cookies, localStorage or logs.
- If the email already had a parent account, the API **links it**: `credentials` is null and `linkedExistingAccount` is true. Show "Linked to their existing account; they sign in with their current password."
- Role changes and deactivation sign the person out everywhere on their next request.
- Deactivated staff disappear from `/lookup`. Their existing class assignments stay visible on the class screens until reassigned.
- An admin editing their own record can't remove Admin or deactivate themselves, and can't reset their own password here (use Change password). The 422 `detail` explains this. Hide or disable those controls on your own record.
- Field errors: `fullName`, `email`, `phone`, `jobTitle`, `roles`.
- Validation to mirror: name ≤ 150, valid email ≤ 256, phone `+?[0-9 ()-]{7,32}`, job title ≤ 100, at least one role from Admin, Teacher, Bursar.

## Screens to build (console, Admin)
1. **Staff list** (`/admin/staff`): search box, Active/Inactive filter, table with staff number, name, email, roles (badges), status, last sign-in, and pagination. Include loading, empty and error states.
2. **Add staff** (dialog or page): form, then the credential slip.
3. **Staff detail/edit** (`/admin/staff/[id]`): edit form, role checkboxes, active toggle (confirm on deactivate), assignments list (read-only, linking to the class), "Reset password" (confirm, then credential slip).
4. **Credential slip** (printable, reusable for students and parents in part 3): school logo and name, person's name, username, temporary password in a large monospace font, sign-in URL, "You'll be asked to choose a new password the first time you sign in." Use `@media print` styles and a Print button. One slip per page.
5. **Turn on the teacher pickers** from part 1 (form teacher, subject teacher) using `GET /api/staff/lookup`.
