# Handoff → Frontend: M1.2 part 4 — Behaviour ratings & clubs (E2.5)

> Backend status as of 2026-10-14. Contract: `contracts/openapi.json` (run `npm run api:types`). Builds on parts 2–3 (report preview, PDF).

## What exists now
- **Affective & psychomotor traits**, each rated **A–E** per student per term. The key is from the school's Excel sheet:
  - A – Exceptional, B – Good, C – Improved, D – Improving, E – Working towards.
- **Default traits (14, seeded):**
  - Accepts criticism, Punctual, Asks for help, Assumes responsibility, Attentive, Care of books and property, Care of personal appearance.
  - Courteous and considerate, Does homework regularly, Does neat work, Participates in group activities, Respects authority, Uses time to good advantage, Works independently.
  - The admin can rename, reorder, add and deactivate traits.
- **Clubs & activities**: up to 6 per report. Each has a name (≤ 40 chars) and an optional free-text rating (≤ 30 chars), e.g. "Coding — Excellent".
- **Never affects results.** Totals, averages, positions and class figures are unchanged (tested).
- **Who can set ratings and clubs:** the class's **form teacher** or an **admin**. Subject teachers get 403 `report.not_form_teacher`.
- **Locked once published.** Changes are refused with 422 `report.published`; unpublishing reopens them.
- **PDF**: there's a new section between the grading key and the comments:
  - The traits in two columns with their letters.
  - Clubs and the rating key beside them.
  - A full report (15 subjects, all traits, 6 clubs) still fits on one A4 page (tested).

## Endpoints
| Method & path | Who | Body → Response | Errors |
|---|---|---|---|
| `GET /api/assessment/behaviour` | Admin, Teacher | → `BehaviourSettings` | 401, 403 |
| `PUT /api/assessment/behaviour` | Admin | `{ traits: { id: string \| null, name: string, isActive: boolean }[] }` → `BehaviourSettings` | 400 (`traits`, `traits[i].name`, duplicate names), 403 |
| `PUT /api/reports/{studentId}/{termId}/behaviour` | Form teacher of the class, Admin | `{ ratings?: { traitId, rating: string \| null }[], clubs?: { name, rating: string \| null }[] }` → `ReportCard` | 400 (`ratings`, `clubs`), 403, 404, 422 `report.published` |

How the save calls behave:
- **Trait list save:**
  - The list order is the report order.
  - A trait left out of the list is deleted, or only deactivated if a report already rated it (`inUse: true`). Published reports keep it.
- **Behaviour save:**
  - It **replaces** everything on that report. A trait left out of `ratings`, or sent with a null/blank rating, becomes unrated. Blank club names are dropped.
  - Ratings are case-insensitive (`"a"` is stored as `"A"`).
  - Any letter other than A–E fails with 400 `errors.ratings`. Unknown trait ids, more than 6 clubs, or duplicate clubs also fail with 400.

## Shapes
```ts
type BehaviourSettings = {
  traits: { id: string; name: string; order: number; isActive: boolean; inUse: boolean }[];
  ratingKey: { rating: string; meaning: string }[];   // A..E
  maxClubs: number;                                    // 6
};
// ReportCard gains (additive):
behaviour: { traitId: string; trait: string; rating: string | null }[]; // active traits + any inactive trait this report rated, in order
clubs: { name: string; rating: string | null }[];
behaviourKey: { rating: string; meaning: string }[];
// ClassReportRow gains:
traitsRated: number;
```

## UI to build
1. **Report card preview → "Behaviour & clubs" card** (editable for the form teacher/admin while Draft, read-only when Published):
   - One row per trait with a compact A–E segmented control (radio group, keyboard-accessible). Show the key as a legend and allow clearing a rating.
   - Clubs: up to 6 rows, each with a name and an optional rating, plus Add and Remove.
   - Save with a single PUT and refresh from the returned `ReportCard`. Show field errors under the section.
   - Show "Doesn't affect scores or position" as helper text.
2. **Class reports list**: add a "Behaviour" column/badge showing `traitsRated / traits.length`, e.g. "14/14". It helps the form teacher see who still needs rating.
3. **Settings → Assessment → "Behaviour traits" tab (admin)**:
   - A reorderable list (name and active toggle), an Add button, and a remove button.
   - Removing a trait with `inUse: true` should say "will be hidden from new reports; kept on old ones".
   - The A–E key is read-only.
   - Use the input-width rules from the grading-scale fix.
4. On a published report, show the same section read-only.

## Notes
- Publishing doesn't require behaviour ratings. Reports without them print the traits with blank ratings, so they can still be filled in by hand.
- Parents and students will see behaviour on the published report in the portal (M1.3, next).
