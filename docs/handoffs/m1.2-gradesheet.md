# Handoff → Frontend: M1.2 part 1 — Assessment settings & score entry (E2.4, E5.1, E5.2)

> Backend status as of 2026-10-13. Contract: `contracts/openapi.json` (run `npm run api:types`). Part 2 (comments, report preview, publish) and part 3 (PDF report card) follow.

## What exists now
- **Admins** configure the score components (default: Project 10 · Homefun 5 · Class Fun 5 · Attendance 10 · CAT 30 · Exams 40 = 100) and the grading scale (A 70+ Excellent … F 0+ Needs Improvement).
- **Teachers** see the classes and subjects they can grade, open a grid for one class + subject + term, and save scores. Totals, grades and remarks are computed server-side.
- **Who can grade what** is enforced by the server:
  - a **subject teacher** grades only their assigned subject in that class;
  - a **form teacher** grades every subject of their own class;
  - an **admin** grades everything.
  Everyone else gets 403.
- Once a student's report is **published**, their scores are locked (422) until an admin unpublishes. Publishing arrives in part 2.

## Endpoints (`/api/assessment`, Admin + Teacher)
| Method & path | Who | Body → response | Errors |
|---|---|---|---|
| `GET /settings` | Admin, Teacher | → `AssessmentSettings { components[], bands[] }` (components in report order; bands highest first) | |
| `PUT /settings` | Admin | `{ components: [{ id?, name, maxScore, isActive }], bands: [{ grade, minScore, maxScore, remark }] }` → `AssessmentSettings` | 400 (`components` / `bands`), 422 `assessment.max_below_scores` |
| `GET /my-classes` | Admin, Teacher | → `GradableClass[] { classRoomId, classRoom, levelOrder, subjectId, subject, isFormClass }` (admin: everything offered) | |
| `GET /gradesheet?classRoomId&subjectId&termId` | the class/subject's grader | → `GradeSheet` | 403 `assessment.not_assigned`, 404 `assessment.subject_not_offered` / `term.not_found` |
| `PUT /gradesheet` | the class/subject's grader | `{ classRoomId, subjectId, termId, entries: [{ studentId, scores: [{ componentId, score: number \| null }], comment? }] }` → refreshed `GradeSheet` | 400, 403, 404, 422 `assessment.report_published` |

```ts
type GradeSheet = {
  classRoomId: string; classRoom: string; subjectId: string; subject: string; termId: string; term: string;
  components: { id: string; name: string; maxScore: number }[];        // active, in column order
  rows: {
    studentId: string; admissionNumber: string; name: string /* "Surname, First" */;
    scores: { componentId: string; score: number | null }[];           // one per component, same order
    total: number | null; grade: string | null; remark: string | null; comment: string | null;
    locked: boolean;                                                     // report published → read-only
  }[];
};
```

## Grid behaviour (E5.1 acceptance criteria)
- **Keyboard first:** Tab / Shift+Tab across a row, Enter / Shift+Enter down and up a column, arrow keys when the input is empty or the caret is at an edge. Inputs use `inputmode="decimal"` (number pad on tablets). Sticky first column (name) and header row; it must work on a 768 px tablet and stay usable at 360 px (horizontal scroll inside the grid only).
- **Live client feedback:** each cell checks 0 ≤ score ≤ component max with at most 2 decimals, highlights invalid cells, and shows a live total plus grade (use `GET /settings` bands; the server's grade is what gets saved).
- **Autosave:** debounce about 1.5 s after the last edit and send **only the changed rows** (the API leaves other students untouched). Show "Saving… / Saved hh:mm / Not saved – retry". On reconnect, retry pending rows. Keep unsaved edits in `sessionStorage` per sheet so a dropped connection doesn't lose work (school Wi-Fi). After a save, replace rows from the response.
- **Empty means cleared:** a row whose scores are all null and comment empty deletes that student's entry.
- **Server errors are per cell:** 400 `errors` keys look like `entries[3].scores.{componentId}` (the index is in **the request's** `entries` array) and `entries[3].studentId`. Map them back to the cell and show the message. Nothing in that request was saved.
- **Locked rows** (`locked: true`) are read-only with a lock icon and the tooltip "Report published – ask an admin to unpublish". A 422 `assessment.report_published` shows `detail`.
- **Optional per-student comment** (≤ 1000 chars) in a last column or an expandable row.

## Screens
1. **My classes** (`/admin/assessment`, teachers and admins): cards or a table from `/my-classes` grouped by class, with a "Form class" badge, a term picker (default: current term from `/api/academics/terms/current`, others from `/api/academics/sessions`), and "Enter scores" → the grid.
2. **Score grid** (`/admin/assessment/[classRoomId]/[subjectId]?termId=`): as above, with a header showing class · subject · term and component maxima.
3. **Assessment settings** (`/admin/settings/assessment`, Admin; read-only for teachers):
   - **Components:** an editable list (name, max, active, drag to reorder) with a running total that must read **100** before Save is enabled. Components with `hasScores` can't be deleted, only made inactive; explain that.
   - **Grading scale:** a table (grade, min, max, remark), lowest min must be 0.
   - Show a warning: "Changing settings doesn't change published reports."
4. Sidebar: "Assessment" for Teacher and Admin.
